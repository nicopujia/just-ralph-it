# Implementation Plan

- Findings from current code state:
  - `Project.chat.send()` is no longer a stub: it ensures initialization, records user/assistant turns to `.jri/logs/interrogation.jsonl`, emits assistant chat events, normalizes exact standalone start triggers into the real auditing lifecycle, surfaces blocked/stopped/running guidance, and verifies existing `needsHumanTask` blockers on `done` so resumed loops can proceed.
  - Bare `jri` now routes piped input through `Project.chat.send()` and prints assistant deltas/status; CLI coverage now includes piped bare-`jri` interrogation.
  - Runtime config loading now uses bundled validation (not raw `JSON.parse`) before use, preventing malformed runtime config shape regressions.
  - A prior recommendation to expose public `jri start`/`jri status` conflicts with the MVP spec, which only allows the public command surface plus bare-`jri` flow and `jri auth`.
  - Interactive bare `jri` now performs auth preflight before opening the interrogator. If auth is missing, execution exits with actionable, scenario-specific guidance. `jri auth login` guidance now distinguishes missing vs stale/expired Pi OpenAI auth entries, which matters because guidance controls whether controlled Pi sessions should start.
  - Explorer capability slice is now implemented: hidden/internal JRI-owned `jri --run-explorer` wraps a read-only Pi command (`pi --print ...`) in spawn-only mode, resolves explorer model, logs `subagentStarted`/`subagentFinished`/`subagentFailed`, emits artifact-backed full outputs, and enforces a 4000-character handoff cap.
