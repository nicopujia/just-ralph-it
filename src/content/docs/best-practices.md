# Best Practices

Follow these guidelines to get the most out of Just Ralph It.

## Writing Good Requirements

### Be Specific

Instead of: "Make a fast website"

Say: "Create a portfolio website with a homepage, about page, and contact form, optimized for mobile devices"

### Provide Context

Share relevant background information:

- Target audience
- Technical constraints
- Design preferences
- Existing codebases or APIs

### Define Acceptance Criteria

Each issue should have clear, testable acceptance criteria:

- "Users can log in with email and password"
- "The homepage loads in under 2 seconds"
- "All forms validate input before submission"

## Working with Issues

### Keep Issues Focused

Each issue should represent a single, atomic piece of work.

### Use Dependencies Wisely

Mark dependencies between issues when order matters.

### Review Before Starting

Check issues for completeness before Ralph begins work.

## Iterative Development

Start with a minimal viable product and iterate:

1. Core functionality first
2. Polish and refinements second
3. Advanced features last
