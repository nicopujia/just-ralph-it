# Best Practices

The most important skill for working with Just Ralph It is communication. Here is how to get better results.

## Start with a Clear Project Idea

Before diving in, have a clear mental picture of what you want to build. You do not need technical details yet, but you should know the core purpose. Think about who will use it and what problem it solves.

If you are unsure, start broad. You can refine as you go.

## Keep Chatting Until Ambiguities Are Resolved

When you describe something to Ralphy, watch for questions back. These questions are not a sign that you have done something wrong. They are the system working as intended.

If Ralphy asks for clarification, answer directly. Do not skip over questions that feel uncomfortable or vague. The quality of the final result depends on how well ambiguities are resolved early.

Common areas where clarification helps:

- Who is the target audience
- What should happen in edge cases
- Whether there are existing tools or code to work with
- How the project should behave under error conditions

## Prefer Concrete Expectations

Vague descriptions lead to vague results. Instead of "make it look nice," try "a simple homepage with a hero section, navigation bar, and a contact form."

Instead of "it should be fast," try "pages should load in under two seconds on a standard connection."

Concrete expectations give Ralphy and Ralph clear targets to hit.

## Keep Refining the Spec Before Ralph Runs

After Ralphy creates the initial set of issues, read through them carefully. Do not rush Ralph to start. If anything looks wrong or missing, ask for adjustments.

Ask yourself:

- Does each issue describe what I actually want?
- Are there any features I forgot to mention?
- Is the order of issues logical?
- Are the acceptance criteria testable?

Refining the spec takes a few minutes and can save hours of back-and-forth later.

## Iterate as You Learn

You will learn things about your own project as you watch it get built. New ideas will come up. That is normal. Do not try to plan everything upfront. Add new issues as you go and let the system adapt.

The more you engage with the process, the better the outcome.
